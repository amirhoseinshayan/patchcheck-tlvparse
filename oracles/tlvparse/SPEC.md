# tlvparse — independent reference behaviour

Status: written by the group from the format definition below.
Expected outputs are derived from this document, never from running any version of the program.
The oracle JSON files and test inputs are generated by `tools/gen_tlvparse_corpus.py`.

## Invocation

`tlvparse FILE`. Wrong argument count: stderr `usage: tlvparse FILE\n`, exit 3.
Unreadable file: stderr `error: cannot open input\n`, exit 3.

## Input format

1. 4-byte magic `TLV1`.
2. Zero or more records: `type` (1 byte), `length` (1 byte, 0–255), `value` (`length` bytes).

| Type | Meaning | Value rules | Output line |
|---|---|---|---|
| 1 | name | 0–32 bytes of text | `name: <value>` |
| 2 | number | exactly 4 bytes, signed 32-bit little-endian | `number: <decimal>` |
| 3 | blob | 0–32 bytes | `blob: <length> bytes, sum=<unsigned sum of bytes>` |

A valid file prints one line per record in file order, then `records: <count>`,
with empty stderr and exit 0. At most 16 records and 65536 input bytes are allowed.

## Errors

On any error, stdout is empty, stderr is exactly one line and the exit code is 2.
Checks apply to records in file order; the first violation decides the message.

| Condition | stderr |
|---|---|
| File shorter than 4 bytes, or magic is not `TLV1` | `error: bad magic` |
| Fewer than 2 header bytes, or fewer than `length` value bytes remain | `error: truncated record` |
| A 17th record is present | `error: too many records` |
| Type is not 1, 2 or 3 | `error: unknown record type` |
| Type 2 with length other than 4 | `error: bad number length` |
| Type 1 or 3 with length greater than 32 | `error: value too long` |
| Input larger than 65536 bytes | `error: input too large` |

## Security property

No input may cause out-of-bounds memory access. In particular, a value longer
than 32 bytes, for any record type, must be rejected with `error: value too long`.
